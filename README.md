# 波段作战台

面向 A 股投资小白的短线辅助工具。只做一种风格：**T+1 到 3～5 日波段**。不打板，不日内交易，不接券商实盘。

它要解决的是纪律，不是「荐股」，更不是保证收益。每笔纸上交易都必须带入场理由、仓位上限、止损、目标和持有天数。页面写明 **不是投资建议**，也不会出现必胜、胜率榜或保证收益的说法。

## 这一刀有什么

1. **今日候选**（最多 5 只）：先扫沪深 A 股公开快照（北交所、B 股不要），再用同一套硬规则复核日K；用人话写放入选原因、结构类型、盈亏比，以及什么情况下作废。
2. **交易计划卡**：买多少（默认单票不超过总资金 20%，即 2 万元）、亏多少走、目标在哪、最多拿几天。
3. **模拟持仓与复盘**：纸上开平仓，受 T+1、最多 3 只、现金缓冲约束；公开延迟行情下浮盈按日K收盘计价。

演示资金 **10 万元**。同时持有不超过 3 只，股票占用最多约 6 万，至少留 4 万现金。

## 硬规则在挡什么

真正生效的规则在 `src/lib/scan-rules.ts`。它们用来少做错结构，**不会**把胜率变成一个可承诺的数字：

- 先扫沪深A股全市场快照（优先 AKShare 的腾讯快照，带量比），再对进入日K复核的票过硬规则。公开接口做不到对 5000 只都拉日K。AKShare 的东方财富接口和我们直连一样经常失败，所以不指望它。
- 一手不超过 2 万；ST、涨停、一字板不要
- 量比 1.2～2.8，爆量高潮不要
- 收盘站上 5 日和 10 日线，且 5 日线不低于 10 日线
- 离开 10 日线：主板不超过 6%，创业板/科创板不超过 8%
- 当日涨幅小于 5%，连涨不超过 2 天；高开超过 4% 当追空处理
- 收盘要落在当日区间上半，长上影、振幅过大不要
- 近 10 日高点要有空间；止损不超过 6%，盈亏比至少 1.3
- 快筛过关但没进入日K复核，不是被判不合格：公开接口每天大约只复核 150 只日K（第一波 0 只再补一波到约 300），剩下的是配额，不是硬规则
- 最多 5 只，按结构排序，不是谁量最大谁上榜

规则变严之后，空仓会更常见。空仓也是计划。

行情默认由**本机 Next 服务端代拉公开延迟日K**（腾讯 `web.ifzq.gtimg.cn` 优先；该域名对 Chrome/部分 Node 常返回 **501**，则改拉新浪日K）。开发者工具请看 `/api/desk` 和 `/api/kline?code=xxxxxx`。拉不到时自动改用离线演示。

## 本地运行

需要 Node.js 20+。全市场快照优先走 AKShare（封装腾讯行情，带量比）。没装 Python 依赖时，仍会退回东方财富/新浪列表。

```bash
python3 -m pip install -r requirements.txt
npm install
npm run dev
```

浏览器打开 [http://127.0.0.1:43127](http://127.0.0.1:43127)。开发服务器默认绑在 `0.0.0.0:43127`。

```bash
npm run build
npm start
```

纸上账户存在浏览器 `localStorage`，用「重置账户」可以回到 10 万空仓。

## 本机仍显示离线演示时

1. `git pull` 后 **停掉再开** `npm run dev`（旧进程不会带上代拉）。
2. 浏览器打开 [http://127.0.0.1:43127/api/kline?code=000001](http://127.0.0.1:43127/api/kline?code=000001)：应是 JSON 且带 `data`。响应头 `x-kline-via` 为 `fetch`/`curl`/`sina`。若仍是 `"腾讯返回 HTTP 501"`，说明还在跑旧进程。
3. 页面右上角不要停在「离线演示」。
4. 红色提示里会写扫描失败原因。

## 刻意不做
